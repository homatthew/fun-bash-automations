# Fun Bash Automations

`fun-bash-automations` is the shared base layer for shell helpers, Git workflow
tools, and harness-agnostic LLM agent behavior. It should stay reusable outside
one private Netflix environment.

## Repository Role

Use this repository for behavior that is broadly reusable:

- shell functions, aliases, and scripts that do not reveal internal topology
- shared agent policy in `llm/AGENTS.md`
- shared skills in `llm/skills/*/SKILL.md`
- shared hooks in `llm/hooks/*.sh`
- portable Codex config in `codex/config.toml`
- portable Codex MCP definitions in `codex/mcp.toml`
- local workflow tools such as `bin/pg`, `bin/stack`, and push-gate helpers

Do not put confidential or machine-specific details here. Jira board topology,
private field IDs, internal service URLs, private Slack lore, team-specific
labels, and internal MCP gateway overlays belong in the private `dotfiles`
repository.

## Relationship To Dotfiles

`dotfiles` consumes this repository as its shared base, then applies private
overlays for a specific Netflix workstation or workspace.

| Layer | Repository | Source of truth | Typical target |
| --- | --- | --- | --- |
| Shared base | `fun-bash-automations` | `llm/`, `codex/`, `zsh/personal.zsh`, `bin/` | `~/.claude`, `~/.codex`, `~/.zsh/personal.zsh`, `~/.local/bin` |
| Private overlay | `dotfiles` | `config/`, root dotfiles, workspace installers | `~/.zsh/netflix.zsh`, internal skills, internal MCPs |
| Local state | home directory | generated by tools | hook trust, model NUX state, project trust |

The final Netflix install should normally run from `dotfiles`, not directly
from this repository. `dotfiles` calls `bin/fba-deploy` to project the shared
LLM base and then layers private config after it.

## Installation Paths

### Shared LLM Runtime Projection

Run `fba-deploy` when you change repo-owned LLM runtime files and want to
refresh local Claude/Codex homes:

```bash
bin/fba-deploy
bin/fba-deploy --codex-only
bin/fba-deploy --claude-only
```

`fba-deploy` renders shared config into `~/.claude` and `~/.codex`. It does not
install private dotfiles overlays.

### Full Netflix Workspace Install

Use the private `dotfiles` repository for a full workspace bootstrap. The
workspace installers clone or locate this repository, run `fba-deploy`, and
apply internal overlays.

### MacBook Shell Setup

Do not use this repository as the final MacBook install if the private
`dotfiles` repository is available. Use the Mac-safe shell link script in
`dotfiles` so `~/.zshrc`, `~/.zshenv`, `~/.zsh/personal.zsh`, and
`~/.zsh/netflix.zsh` point at the intended two-repo layout.

`setupPermissions.sh` remains a legacy local bootstrap script. Prefer the
`dotfiles` install guide for current machine setup.

## Contribution Guide

1. Put reusable behavior in this repository first.
2. Move behavior to `dotfiles` only when it depends on confidential Netflix
   details, private auth, internal-only tools, or one user's workstation state.
3. Edit shared LLM policy in `llm/AGENTS.md`, not in projected home files.
4. Edit shared skills in `llm/skills/*/SKILL.md`.
5. Edit portable Codex MCPs in `codex/mcp.toml` and document install/auth notes
   in `codex/MCP.md`.
6. Run `bin/fba-deploy` after changing projected runtime files.
7. Verify projection with:

```bash
tests/projection-regression.sh
```

## Delivery Policy

This repository uses `mh-netflix` as its delivery branch and does not use
push-gate. Agents may push to `mh-netflix` only after the user explicitly asks
for a push or invokes an explicit finish workflow. Do not create PRs from
`mh-netflix` to `main`.

The shared push policy (`llm/agent-push-policy.json`) defines four branch
classes: **delivery** (push-gate), **scratch** (`wip/agent/`, `scratch/agent/` —
opt-in Remote Scratch Mode, not PR-eligible), **direct-push exceptions**
(`fun-bash-automations`, `dotfiles`), and **yolo** (`mho-yolo/*` — raw push + PR
fast path on any repo, no push-gate, force-with-lease and delete allowed, and
structurally unable to target or track a base ref). See the `yolo-pr` skill.

# Fun Bash Automations

`fun-bash-automations` is the shared base layer for shell helpers, Git workflow
tools, and harness-agnostic LLM agent behavior. It should stay reusable outside
any one private environment.

## Repository Role

Use this repository for behavior that is broadly reusable:

- shell functions, aliases, and scripts that do not reveal internal topology
- portable personal Git defaults and global ignore rules in `git/`
- shared agent policy in `llm/AGENTS.md`
- shared skills in `llm/skills/*/SKILL.md`
- shared hooks in `llm/hooks/*.sh`
- portable Codex config in `codex/config.toml`
- portable Codex MCP definitions in `codex/mcp.toml`
- local workflow helpers in `bin/` such as `fba-deploy` and notification tooling

Do not put confidential or machine-specific details here. Jira board topology,
private field IDs, internal service URLs, private Slack lore, team-specific
labels, and internal MCP gateway overlays belong in the private `dotfiles`
repository.

## Relationship To Dotfiles

`dotfiles` consumes this repository as its shared base, then applies private
overlays for a specific workstation or workspace.

| Layer | Repository | Source of truth | Typical target |
| --- | --- | --- | --- |
| Shared base | `fun-bash-automations` | `llm/`, `codex/`, `zsh/personal.zsh`, `git/`, `bin/` | `~/.claude`, `~/.codex`, `~/.zsh/personal.zsh`, `~/.config/git/ignore`, `~/.local/bin` |
| Private overlay | `dotfiles` | `config/`, root dotfiles, workspace installers | `~/.zsh/local.zsh`, internal skills, internal MCPs |
| Local state | home directory | generated by tools | hook trust, model NUX state, project trust |

The final private-workspace install should normally run from `dotfiles`, not directly
from this repository. `dotfiles` calls `bin/fba-deploy` to project the shared
LLM base and then layers private config after it.

## Installation Paths

### Shared LLM Runtime Projection

Run `fba-deploy` when you change repo-owned LLM runtime files and want to
refresh local Claude/Codex homes:

```bash
bin/fba-deploy
bin/fba-deploy --codex-only
bin/fba-deploy --claude-only
```

`fba-deploy` renders shared config into `~/.claude` and `~/.codex`. It does not
install private dotfiles overlays.

### Full Private Workspace Install

Use the private `dotfiles` repository for a full workspace bootstrap. The
workspace installers clone or locate this repository, run `fba-deploy`, and
apply internal overlays.

### MacBook Shell Setup

Do not use this repository as the final MacBook install if the private
`dotfiles` repository is available. Use the Mac-safe shell link script in
`dotfiles` so `~/.zshrc`, `~/.zshenv`, `~/.zsh/personal.zsh`, and
`~/.zsh/local.zsh` point at the intended two-repo layout.

`setupPermissions.sh` remains a legacy local bootstrap script. Prefer the
`dotfiles` install guide for current machine setup.

### Portable Git Preferences

The `git/` directory preserves reusable personal Git behavior without copying
identity, credentials, proxy settings, or private conditional includes. To use
it on another Unix machine, link the global ignore file and include the portable
config fragment:

```bash
mkdir -p ~/.config/git
test -e ~/.config/git/ignore || \
  ln -s ~/repos/fun-bash-automations/git/ignore ~/.config/git/ignore
git config --global --get-all include.path | \
  grep -Fxq ~/repos/fun-bash-automations/git/personal.gitconfig || \
  git config --global --add include.path ~/repos/fun-bash-automations/git/personal.gitconfig
```

## Project Worktrees

The shared zsh layer includes a generic `proj` helper for switching between
multi-repo worktree projects:

```bash
proj                         # select an existing project with fzf, or list them
proj --list                  # list existing projects
proj my-project              # cd to ${PROJECTS_DIR:-~/proj}/my-project
proj my-project api worker   # create worktrees from ~/repos/api and ~/repos/worker
```

Set `PROJECTS_DIR` to move project folders somewhere other than `~/proj`.
Set `REPOS_DIR` if your source clones live somewhere other than `~/repos`.
Zsh completion for `proj` shows existing projects with repo counts and source
repo candidates with branch/dirty status. The `rp` completion uses the same
`REPOS_DIR` source and shows command, repository, and archived-repository
candidates with descriptions.
Private repo discovery, internal clone URLs, and workspace-specific bootstrap
logic belong in the `dotfiles` overlay.

## Contribution Guide

1. Put reusable behavior in this repository first.
2. Move behavior to `dotfiles` only when it depends on confidential company
   details, private auth, internal-only tools, or one user's workstation state.
3. Before delivery, audit both the outgoing tree and any commit history being
   added to public `main`. Rebuild a clean snapshot from public `main` instead
   of publishing unaudited local history.
4. Edit shared LLM policy in `llm/AGENTS.md`, not in projected home files.
5. Edit shared skills in `llm/skills/*/SKILL.md`.
6. Edit portable Codex MCPs in `codex/mcp.toml` and document install/auth notes
   in `codex/MCP.md`.
7. Run `bin/fba-deploy` after changing projected runtime files. It also installs
   the composable pre-push boundary hook and pins the local no-mistakes binary
   identity used for direct `main` delivery.
8. Verify projection with:

```bash
tests/projection-regression.sh
```

## Delivery Policy

This repository uses `main` as its delivery branch and delivers directly to it.
Agents may push to `main` only after the user explicitly asks for a
push or invokes an explicit finish workflow. The finish-the-job entrypoint is the
`/ship` skill, which runs the `no-mistakes` gate (automated code review, tests,
lint, docs) before pushing. Do not create PRs for this direct-push repository.
Run `scripts/check-push-safety.sh --install-hook` before the first delivery from
a newly prepared checkout, supplying `FBA_NO_MISTAKES_TRUSTED_PATH` and
`FBA_NO_MISTAKES_TRUSTED_SHA256` from a private trust policy. The hook fails
closed when that independently trusted identity is absent or no longer matches.
Environment-specific publication detectors can be supplied from a private
tab-separated policy file through `FBA_PUSH_SAFETY_POLICY_FILE`; the public
scanner retains only portable credential and filesystem-boundary detectors.
Hook installation records the explicitly selected external policy path in the
local Git hook directory so later pushes fail closed against the same policy.
Routine reinstall validates and preserves that policy and the no-mistakes trust
attestation. Clear them only with `FBA_PUSH_SAFETY_CLEAR_POLICY=1` or
`FBA_NO_MISTAKES_CLEAR_TRUST=1`.

The legacy `mh-netflix` ref is a one-time compatibility mirror, not a delivery
branch. After the validated `main` snapshot is delivered, a maintainer may move
that legacy ref outside repository automation and must verify both remote refs
resolve to the same object:

```bash
main_oid=$(git ls-remote --refs origin refs/heads/main | awk '{print $1}')
legacy_oid=$(git ls-remote --refs origin refs/heads/mh-netflix | awk '{print $1}')
test -n "$main_oid" && test "$main_oid" = "$legacy_oid"
```

The shared push policy (`llm/agent-push-policy.json`) defines **delivery**
(no-mistakes gate), **scratch** (`wip/agent/`,
`scratch/agent/` — opt-in Remote Scratch Mode for backup/handoff, not
PR-eligible; promotion to a delivery branch goes through the no-mistakes gate),
and **direct-push exceptions** (`fun-bash-automations`). The schema retains a
disabled yolo branch class for private overlays; the public baseline provides no
ungated force, delete, or PR fast path.
